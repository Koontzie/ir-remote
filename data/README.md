# `data/` — the IR code database

Everything in this directory is generated by
[`tools/flipper_ir_convert.py`](../tools/flipper_ir_convert.py) from
[**Lucaslhm/Flipper-IRDB**](https://github.com/Lucaslhm/Flipper-IRDB), which is
released under **CC0-1.0** (public domain dedication). Nothing here is
hand-written, and nothing here comes from any other source — see
[Provenance](#provenance) below for why that matters.

## Layout

| Path | What it is |
|---|---|
| `db/index.json` | Categories → brands → shard path + per-function counts. The app loads this at startup. |
| `db/search.json` | One compact record per brand (brand, category, canonical functions, model strings). ~61 KB — powers the search box without fetching any shards. |
| `db/<category>/<brand>.json` | One shard per brand, lazy-loaded when you open that brand. |
| `db/unmapped-names.txt` | Button names the canonicaliser did **not** recognise, with occurrence counts. A worklist, not an error log. |
| `sweep-tv.json`, `sweep-projector.json` | Ordered power-code lists for Identify mode's sweep. |

Totals: **8 categories, 317 brands, ~11.1K sendable codes** (plus ~2.6K RAW
timing arrays that the firmware can't send yet).

## Code entries

Each shard is a flat array. A representative entry:

```json
{"name":"power_toggle","orig":"Power","brand":"Samsung","model":"Samsung",
 "proto":"SAMSUNG","code":"0xE0E040BF","bits":32,"nmodels":36,"generic":true}
```

| Field | Meaning |
|---|---|
| `name` | Canonical function (`power_on`, `input_hdmi1`, `vol_up`, …). Anything the canonicaliser wasn't confident about becomes `other:<original>` — it guesses at nothing. |
| `orig` | The original IRDB button name, always preserved. |
| `model` | The `.ir` filename the code came from. |
| `proto` / `code` / `bits` | Ready for IRremoteESP8266. `proto` is `RAW` for timing arrays, which carry `freq` + `data` instead of `code`. |
| `nmodels` | How many distinct models in this brand share this exact code. Absent means one. |
| `generic` | Set when `nmodels >= 3` — a brand-wide "blanket" code, the universal-remote sweet spot. The app floats these to the top of a brand's list. |

**The conversion is not a copy.** Flipper stores address/command bytes LSB-first;
IRremoteESP8266 wants an MSB-first assembled frame. Each byte is bit-reversed and
the frame built per protocol (NEC: `addr,~addr,cmd,~cmd`; Samsung32:
`addr,addr,cmd,~cmd`; NECext: `addr16,cmd,~cmd`; SIRC: `addr<<7|cmd`). That math
is bench-validated — it reproduces `SAMSUNG 0xE0E040BF`, the code physically
verified against the test TV.

## Sweep lists

Identify mode fires power codes one at a time until the device reacts, so the
order is the whole game. `build_sweep_from_db()` builds each list by:

1. Taking every non-RAW power code from the relevant categories (`tv` draws from
   `tvs` + `monitors`, since the app maps monitors onto the TV list; `projector`
   from `projectors`).
2. Summing each code's **model spread** across every brand — the same signal
   behind the `generic` flag, widened from one brand to a whole category.
3. Deduping by `(proto, code)`, keeping the canonical reading with the most
   models behind it.
4. Sorting `power_on` → `power_toggle` → `power_off`, and **spread-descending
   within each group**.

The group order outranks hit rate on purpose: a discrete `power_on` can't turn
off a device that's already on, so it's safe to try first, while a toggle sent at
a device that's already awake looks exactly like a miss.

Current sizes: **70 TV codes** (~28s at 400 ms/code) and **57 projector codes**
(~23s). The widest-spread entries are LG `NEC 0x20DF10EF` (57 models), Samsung
`0xE0E040BF` (39) and Sony `0x95` (27).

## Regenerating

```sh
git clone --depth 1 https://github.com/Lucaslhm/Flipper-IRDB.git /tmp/Flipper-IRDB
python3 tools/flipper_ir_convert.py --scrape /tmp/Flipper-IRDB --out data/db
```

Clone to a temp directory, **not** into this repo. The run rewrites `db/` and
both sweep lists, then checks four sanity gates and exits non-zero if any fail:

- the bench-verified `SAMSUNG 0xE0E040BF` is present in the Samsung TV shard
- the NEC projector shard has discrete `power_on` *and* `power_off`
- blanket-code promotion actually fired for Samsung TVs
- `search.json` exists and indexes Samsung TVs

The scrape is deterministic — re-running against the same upstream commit
produces byte-identical output, so a non-empty `git diff` on `data/db/` means
upstream genuinely changed.

## Provenance

The database is **CC0-1.0** throughout, which imposes no conditions on reuse.
It is credited anyway, in the README and here, because that's good manners.

Until 2026-07-31 the two sweep lists were built from a different source, and the
full record of what that was matters more than the fact it's gone:

`data/source/tv.ir` (613 entries, 295 power codes) and
`data/source/projectors.ir` (302 entries, 138 power codes) were the universal IR
library assets shipped with the Flipper Zero **Unleashed** firmware, taken from
`applications/main/infrared/resources/infrared/assets/` in
[DarkFlippers/unleashed-firmware](https://github.com/DarkFlippers/unleashed-firmware).
Their file headers date them 2024-10-05; they were fetched for this project on
2026-07-19. Those assets in turn build on the
[official Flipper Zero firmware](https://github.com/flipperdevices/flipperzero-firmware)
(also GPL-3.0) and on community submissions to Flipper-IRDB (CC0-1.0).
`data/tv.json` and `data/projectors.json` were machine conversions of them, and
therefore derived works carrying the same terms.

**Unleashed is GPL-3.0**, which is copyleft: anything redistributing those assets
has to be GPL-3.0-compatible, and MIT is not. So when this project took an MIT
license, the two `.ir` files, both converted `.json` outputs, and the converter
code path that read them were removed, and the sweep lists were rebuilt from the
CC0 database instead — the option the original attribution note had already
identified as the way out of the constraint.

⚠️ **The removed files remain in this repository's git history**; history was not
rewritten. That's deliberate — deleting going forward is proportionate, and
force-pushing would break every existing clone to no real benefit. Nothing in the
current tree derives from them.
